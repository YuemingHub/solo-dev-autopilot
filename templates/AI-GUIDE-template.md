## 幻觉：AI 会"一本正经地胡说"

### 什么是幻觉？

AI 有时候会编造不存在的 API、函数、库，说得非常自信。比如：
- 编一个 `Array.flatMapDeep()` 方法（实际不存在）
- 推荐一个 `react-super-form` 库（实际不存在）
- 给你一个错误的用法（参数顺序搞反）

**这不是 AI 故意骗你，是它的生成机制决定的——它在"预测最可能的下一个词"，而不是"查找真实信息"。**

### 怎么防幻觉？3 条规则

#### 规则 1：AI 给的 API/函数名，先验证再使用

```
❌ 直接复制 AI 给的代码就跑
✅ 对 AI 说："你给的 xxx API 是真的吗？在哪个文档里？"
```

常见验证方式：
- 查官方文档（比如 MDN 查 JS API，npm 查包是否存在）
- 对 AI 说"搜索一下这个 API 是否存在"
- 在终端跑一下试试：`node -e "console.log(typeof Array.prototype.flatMapDeep)"`

#### 规则 2：每写一步就跑一下

```
❌ 让 AI 一口气写完 5 个功能，最后一起跑
✅ 写完一个功能就跑一次，确认没问题再继续
```

这样做的好处：
- 出错时你知道是哪一步的问题
- 不会让错误堆叠到最后无法收场
- AI 也能根据实际报错修正，比瞎猜准

#### 规则 3：看不懂的代码不要直接用

```
❌ AI 写了一段你完全看不懂的代码，直接粘贴
✅ 对 AI 说："解释一下这段代码每一行在干什么"
```

如果 AI 解释后你还是看不懂：
- 说"有没有更简单的写法"
- 说"这个设计模式是不是太复杂了？MVP 阶段能不能简化"

> ⚠️ 你看不懂的代码 = 以后出 bug 你修不了的代码。

## 搜索引擎式提问 vs 协作式提问

很多人习惯了用搜索引擎的方式问 AI，效果很差。差别在这里：

### 搜索引擎式（效果差）

```
你：React 怎么写表单
AI：（给一段通用的表单代码，跟你的项目无关）
```

问题：AI 不知道你的项目用什么技术栈、什么 UI 库、表单做什么用。

### 协作式（效果好）

```
你：我在做一个博客系统，用 React + Vite + Tailwind + shadcn/ui。
    需要一个文章发布表单，包含标题、正文、封面图上传。
    后端 API 是 POST /api/posts，字段是 title/content/coverImage。
    帮我写这个表单组件。

AI：（给出完全贴合你项目的代码，包括验证、提交、错误处理）
```

差别：你给的上下文越多，AI 的回答越精准。

### 协作式提问的 4 要素

每次提问，尽量包含这 4 个要素：

| 要素 | 例子 |
|------|------|
| **背景** | "我在做一个博客系统，用 Bun + Hono + React" |
| **目标** | "需要实现用户注册功能" |
| **约束** | "用 PostgreSQL，邮箱+密码登录，不要 OAuth" |
| **当前状态** | "数据库还没建表，路由文件还没创建" |

不需要每次都 4 个全说，但越多越好。如果你不知道怎么说，就念启动咒语让 AI 先读记忆文件，它就自动知道背景了。

## 你是 driver，AI 是副驾

### 不要害怕质疑 AI

AI 不是权威，它也会犯错。如果你觉得 AI 的方案不对劲：

| 场景 | 怎么质疑 |
|------|---------|
| 方案太复杂 | "这个是不是过度设计了？MVP 阶段能不能简单点" |
| 跟你想的不一样 | "我想要的是 xxx，你这个好像偏了" |
| AI 跑偏了 | "停，回到正题，我们当前要做的是 [念 SESSION_DRIVER 目标]" |
| 不确定对不对 | "这个方案有没有风险？有没有更简单的替代方案？" |
| AI 纠缠一个方向 | "换一个思路，试试 xxx 方案" |

### 什么时候该打断 AI

- AI 开始做你没要求的事 → 打断
- AI 越聊越复杂，加了你没要的功能 → 打断
- AI 反复改同一个错误改不好 → 打断，换思路
- 你看不懂 AI 在干什么 → 打断，让它解释

> 💡 **打断不 rude。不打断才是对自己的项目不负责。**
