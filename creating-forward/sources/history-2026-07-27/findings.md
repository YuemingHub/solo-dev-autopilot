## 已确认产品方向

- 中文名：知行合伙人
- 英文名：Creating Forward
- 核心理念：用户负责“知”，系统负责“行”。
- 产品不是首先面向普通用户的 Web 平台，而是一套可被 AI Agent 加载的工作规范、提示词、技能或 Agent 配置。
- 普通用户打开一个 AI Agent，将“知行合伙人”交给它加载；加载后的 Agent 按规范执行任务。
- 核心流程：理解需求、提出极简澄清问题、选择有人值守或无人值守、执行一步、用证据验证、无误后推进下一步。
- 两种工作模式：用户在电脑前时，每个关键决策点停下来核对；用户忙或离开时，使用合理默认值继续，并记录代做决定。
- 用户语言：使用“我在 / 你先做”，内部可映射为同步 / 异步。
- “我在”模式：只在关键决策点停顿，普通小任务执行并验证后自动推进。
- “你先做”模式：可代做的任务按默认方案继续；必须用户亲自完成或属于关键决策的部分不执行、不假装完成，先绕过可独立推进的部分，并记录待用户回来处理。
- 用户回来并说“我在”后，Agent 立即切换为有人值守，在当前或下一个关键节点强制暂停核对。
- 首发任务类型仍可优先选择软件产品创作，但产品本身应是跨任务类型的 Agent 工作协议，而不是只服务一个 Web 应用。
- 目标承载范围：所有主流 AI Agent，因此核心协议必须平台无关，并通过适配层接入不同平台。
- 首期交付目标：用户加载一个极简 Skill/规则包，Agent 即按知行合伙人的提示规范工作。
- 首期最小交付物：可加载 Skill 包，包含核心提示词、工作状态模板、任务循环模板、决策记录模板和软件创作示例。
- Skill 与 MCP 的职责需要分开：Skill 定义工作方法和行为规范，MCP 仅在需要统一外部工具或服务时提供能力。
- Web 界面若需要，应是后续用于配置、观测和复盘的辅助工具，不是第一阶段的核心交付。

## 设计约束

- 用户不应被要求从零填空，应由系统提供经过推理的选项。
- 首期要验证主流程，不扩张到真实代码生成、部署和复杂外部集成。
- 需要保留 Prompt Engineering、Loop Engineering、Graph Engineering 三层理念的可演进边界。
- 每一步完成必须有可检查的验证证据，不能只依赖 Agent 自述。
- 无人值守必须设定高风险动作的硬暂停边界。
- 无人值守的安全边界不是简单地停止全部高风险动作，而是识别“可代做、可跳过、必须由人完成”三类任务。
- 工作流必须支持中断恢复、失败重试、回退和动态插入任务。
- 需要统一的状态、任务、验证和决策记录格式，便于跨 Agent 接力。
- “用户加载即用”是首期体验原则，复杂配置不应暴露给普通用户。

## 方向纠偏

- 之前将 MVP 误解为“可预览的前后端 Web 产品”，该假设已被用户纠正，不再作为产品核心。
- 当前首要问题变为：确定 Agent 的承载平台和可加载机制，再设计可移植的工作协议。
