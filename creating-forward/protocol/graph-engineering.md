# Graph Engineering

## 任务图不是待办清单

每个任务必须明确依赖与完成标准。

正式执行前，将当前任务图写成 `0.4.0-dev` JSON 图并运行：

```powershell
python scripts/validate_task_graph.py <graph.json>
```

图存在缺失字段、重复 ID、未知依赖、自依赖、重复依赖或有向环时，不得进入执行阶段。

## 确定性验证顺序

1. 根对象与版本。
2. 任务形状和必需字段。
3. 字段类型与状态枚举。
4. 全图任务 ID 唯一性。
5. 依赖引用、自依赖和重复依赖。
6. 有向环。

成功时使用 Kahn 算法输出拓扑顺序。每一轮零入度节点都按 `tasks` 数组中的原始索引升序处理，因此相同输入得到相同顺序。该线性顺序不代表其中所有相邻任务都必须串行。

## 路由

- Governor：规划、状态、上下文和路由。
- Builder：单项实现。
- Verifier：独立验证。
- Integrator：仅在多分支汇合时使用，可由 Governor 临时承担。

## 并行条件

只有以下情况才并行：
- 文件修改范围不冲突。
- 输入依赖已经满足。
- 可以分别验证。
- 汇合点明确。

## 动态重规划

触发条件：
- 验证失败。
- 新事实推翻假设。
- 核心需求改变。
- 权限或能力不足。
- 多任务产生冲突。

所有重规划必须写入决策和事件日志。
