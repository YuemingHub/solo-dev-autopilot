# Requirement Engineering

## 前置核对的原则

前置核对不是一次问完所有细节，而是优先确认会造成大面积返工的变量。

### 必须前置确认
- 问题是什么。
- 为谁解决。
- 最终交付什么。
- 成功标准。
- 核心伦理与产品边界。
- 不可接受结果。
- 不可逆技术或数据选择。
- 首期明确不做什么。

### Agent 可默认决定
- 文件命名。
- 普通目录拆分。
- 可替换库。
- 临时合成数据。
- 普通 UI 间距。
- 测试文件位置。

### 执行中渐进澄清
- 代码冲突。
- 依赖不可用。
- 测试暴露的边界。
- 新事实导致的局部设计变化。

## 一个问题规则

每次最多提出一个问题。
默认提供 2–4 个真实差异选项。
第一项可作为推荐，并说明一句理由。
