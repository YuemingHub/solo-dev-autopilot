# MingOS 真实验证计划

## 验证目标

不是证明 AI 可以无限自主工作，而是证明：

- 用户不需要承担机械式项目管理。
- Agent 能在上位约束下准确执行。
- 完成结论有证据。
- 中断和换 Agent 不丢失事实。
- 高风险动作保持人工控制。
- 真实失败能够改进协议而不是制造更多复杂度。

## Phase 0：项目事实可接手

成果：
- 当前事实基线。
- 分支和 PR 图谱。
- 当前运行与产品能力基线。
- 已知债务。
- 自主开发边界。
- 恢复测试。

## Phase 1：单一真实开发闭环

选择一个低风险、明确、可验证的任务。
流程：
- 需求基线。
- 任务图。
- Builder 实现。
- 独立验证。
- Draft PR。
- 中断恢复。
- 运行复盘。

## Phase 2：多任务依赖图

选择包含至少三个依赖节点和两个可并行任务的工作。
验证：
- 上下文包是否正确。
- 并行修改是否冲突。
- 汇合验证是否有效。
- 用户干预是否只发生在关键点。

## Phase 3：跨 Agent 接力

在两个不同本地 Agent 环境中：
- Agent A 规划并完成部分任务。
- Agent B 仅凭工作区恢复并继续。
- 对照事实、决策、证据和剩余任务。

## Phase 4：协议候选迭代

从前述运行中选择一个稳定复现的通用失败：
- 记录观察。
- 分类归因。
- 创建候选变更。
- 增加测试。
- 验证修复。
- 形成 v0.3 Draft。

## 核心指标

- 每个核心成果的证据覆盖率。
- 不必要的人类询问次数。
- 关键人工决策漏停率。
- 无授权动作发生率。
- 中断恢复准确率。
- 重复执行和空转次数。
- 因上下文错误导致的返工。
- Builder 自述被 Verifier 推翻次数。
- 项目特有问题误升为 Core 规则次数。
