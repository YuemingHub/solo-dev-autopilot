# 项目发现

## 来源关系

- `D:\LifeOs\Creating Forward` 是 2026-07-27 的产品探索与 PRD 工作区。
- bootstrap v0.1 是第一版可执行协议包。
- bootstrap v0.2 是当前最新工程化基线，增加产品谱系、治理演进、MingOS Adapter、迁移脚本和真实验证计划。
- v0.2 的 `sources/history-2026-07-27/` 与早期工作区四份材料 SHA-256 完全一致。

## 完整性证据

- v0.2 `MANIFEST.json` 的 44 个文件哈希全部匹配。
- 三个 Python 脚本通过 `py_compile`。
- 临时项目执行 `init_workspace.py` 后，`validate_workspace.py` 返回 `VALIDATION: PASSED`。
- v0.1 有 26 个文件，v0.2 有 44 个文件；v0.2 明确包含 v0.1 迁移策略。

## 架构判断

- 产品本体是平台无关工作协议，不是 MingOS 的一部分。
- MingOS 是首个正式验证环境，不应反向成为通用 Core 的命名和使命。
- v0.2 的协议主体大部分可直接复用，但顶层 `SKILL.md`、README、START_HERE 和脚本参数仍带 MingOS 偏置。
- 主库应保留三类资产：通用 Core、项目 Adapter、历史与验证材料。

## 当前边界

- 本轮只完成主库归一化和第一轮分层，不扩展 MCP、云状态、Web 观测界面或多用户协作。
- `08_迭代日志` 中的版本包只读，不在原处修订。
- Coze CLI 已识别登录状态，但令牌刷新受到 `slow_down` 限流；它不是本地归一化的阻塞条件。

## 独立审查结论

- 第一轮审查发现迁移非原子、Adapter 合并丢失、授权字段冲突、状态校验过弱和 v0.1 迁移不幂等；均已转为回归测试并修复。
- 第二轮审查发现未知版本和错层授权仍可通过、损坏事件日志会留下部分目录、Adapter 权限语义和加载顺序存在歧义；均已修复。
- 通用 Core-only 包不再要求 `adapters/mingos.md`，Adapter 目录提供独立目录入口。
- `evals/` 当前是符合性场景定义，不是已执行通过的行为测试；真实执行必须另存输入、证据和结果。

## 下一迭代候选

- 将任务图引用完整性和环检测做成确定性验证器。
- 将符合性场景升级为带输入、初始状态、预期行为和证据的可执行评估。
- 评估是否引入受控 YAML 解析依赖；当前迁移器明确只支持本项目生成的 YAML 子集。

## 任务图验证设计判断

- 当前 `task.schema.json` 只定义单个任务，无法证明多个任务之间的引用完整性或无环性。
- 任务图验证应使用 JSON 包装对象 `{ "version": "0.4.0-dev", "tasks": [...] }`，避免在没有 YAML 解析依赖时继续用正则扩展行为逻辑。
- 验证器应返回全部可确定错误，而不是遇到第一项即退出；环检测只需报告至少一组环内节点。
- 成功输出包含稳定拓扑顺序，便于 Governor 选择 ready 任务；同层节点按输入顺序保持确定性。
- 符合性场景只能自动检查结构性事实，涉及 Agent 对话和授权判断的场景仍需真实运行证据。
