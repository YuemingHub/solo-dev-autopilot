# Task Planner — 目标拆解与防漂移器

## 目标

把新手的模糊想法（"我想做个博客"）拆解成**具体、可执行、30 分钟能完成**的小任务，
写入 SESSION_DRIVER.md，让新人永远知道"下一步做什么"。

## 执行流程

### Step 1: 收集想法

先问新人：

> "你想做什么？不用想清楚，把你脑子里的想法都说出来，我帮你整理。"

把新人的零散想法全部记录下来，**先不评判、不删减**。
如果新人说不清楚，用以下问题引导：

1. **你想做的东西最终长什么样？**（一句话就行，比如"一个可以发文章的博客"）
2. **谁会用它？**（自己用 / 给别人用 / 上线给陌生人用）
3. **你觉得最核心的功能是什么？**（没有它这东西就没意义的那个功能）
4. **有没有什么必须有的？**（比如必须支持手机、必须用某个技术）

把所有想法写入 SESSION_DRIVER.md 的"想法收集区"。

### Step 2: 定义 MVP

从所有想法中，提取**最小可用版本（MVP）**：

> MVP = 砍掉所有"有了更好"的功能，只保留"没有就不行"的功能。

原则：
- MVP 只做 **1 个核心功能**
- MVP 不做：用户系统（先硬编码）、权限管理、缓存、微服务、CI/CD、监控
- MVP 的标准：**能跑起来、能演示核心流程**

输出格式：
```markdown
## MVP 定义
- 一句话目标：<具体到能演示的程度>
- 核心功能（1个）：<比如"能发布文章并在首页看到列表">
- 不做的事：<列出所有砍掉的>
- 完成标准：<怎么算做完了>
```

### Step 3: 拆解任务

把 MVP 拆成**阶段**，每个阶段拆成**任务**，每个任务 30 分钟能完成。

拆解原则：
- 每个任务必须能**独立完成和验证**（不是"写后端"这种模糊的，而是"创建数据库 users 表"）
- 任务之间有**先后顺序**（先建表才能写 API，先写 API 才能写前端）
- 每个任务标注**预估难度**（简单/中等/复杂），新人优先做简单的

输出格式：
```markdown
## 任务清单

### 阶段 1：基础搭建
- [ ] 1.1 初始化项目结构（简单）— 预计 10 分钟
- [ ] 1.2 配置数据库连接（简单）— 预计 15 分钟
- [ ] 1.3 创建数据库 schema（中等）— 预计 30 分钟

### 阶段 2：核心功能
- [ ] 2.1 写后端 API（中等）— 预计 30 分钟
- [ ] 2.2 写前端页面（中等）— 预计 30 分钟
- [ ] 2.3 前后端联调（中等）— 预计 20 分钟

### 阶段 3：完善
- [ ] 3.1 错误处理（简单）— 预计 15 分钟
- [ ] 3.2 基础样式（简单）— 预计 20 分钟
```

将任务清单写入 SESSION_DRIVER.md 的"当前进度"区块。

### Step 4: 确认本轮目标

从任务清单中选出**本轮要完成的 1-3 个任务**（不要贪多）：

> "这次会话，我们先把 1.1 和 1.2 做完。其他的下次再说。"

写入 SESSION_DRIVER.md 的"本轮目标"区块。

如果新人对选哪些任务犹豫不决：
- 建议从**阶段 1 的第一个任务**开始
- 告诉新人："不用想后面的，先把这个做了，做完再说下一步"

### Step 5: 开始执行

确认目标后，立即开始第一个任务。每完成一个任务：
1. 在 SESSION_DRIVER.md 里打 `[x]`
2. 对新人说"完成了 XXX，下一个是 YYY，继续吗？"
3. 如果新人说继续，直接开始下一个

## 防漂移机制

### 执行前检查

**每次开始做一个新任务前，AI 必须先读 SESSION_DRIVER.md 的"本轮目标"**，确认：
- 这个任务是否在本轮目标的范围内？
- 如果不在，是否是新人明确要求的？

如果发现偏离：
> "停——当前本轮目标是 [念出来]。你现在让我做的 XXX 不在这个范围内。
> 要不要先完成本轮目标？还是你想调整目标？"

### 执行中检查

在执行过程中，如果 AI 发现自己开始做跟目标无关的事：
1. 立即停下来
2. 告诉新人"我发现我在做 XXX，但这不是本轮目标。要不要继续？"
3. 等新人确认后再继续

### 功能蔓延检查

如果新人在执行过程中说"能不能顺便加个 XXX 功能"：
1. 先记到 SESSION_DRIVER.md 的"想法收集区"（不丢）
2. 提醒："这个想法不错，我先记下来。但本轮目标是 XXX，我们先完成它，下轮再做这个？"

> 原则：新想法不丢，但不让它打断当前目标。

## 使用方式

### 触发方式

在对话中说：
- "我想做个 xxx" → 自动触发
- "帮我拆解任务" → 自动触发
- "我不知道从哪开始" → 自动触发
- "下一步做什么" → 读取 SESSION_DRIVER.md 告诉你
- "/skill task-planner" → 手动触发

### 与其他 Skill 的配合

| 场景 | 流程 |
|------|------|
| 新项目启动 | task-planner 拆解 → fullstack-scaffold 建项目 |
| 会话开始 | 读 SESSION_DRIVER.md → 告诉新人"上次做到哪，下一步做什么" |
| 会话中跑偏 | 防漂移机制触发 → 拉回正轨 |
| 会话结束 | post-session 更新 SESSION_DRIVER 进度 |

## 注意事项

1. **永远从 MVP 开始**：新手最常犯的错就是想一次做太多。强制砍到最小。
2. **任务粒度要小**：30 分钟能完成的任务，不是 3 小时的任务。太大会让新人焦虑。
3. **想法不丢**：所有"以后可能要做"的想法都写入想法收集区，让新人安心。
4. **一次只做一件事**：本轮目标最多 3 个任务，多了就拆到下一轮。
5. **完成感很重要**：每完成一个任务就打勾 + 告诉新人"完成了"，给正反馈。
6. **不要替新人决定需求**：AI 帮拆解和排序，但"做什么"由新人决定。
